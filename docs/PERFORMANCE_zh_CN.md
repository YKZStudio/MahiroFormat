# 性能审阅与回归验证

## 范围与取舍

本次审阅覆盖桌面主进程边界、渲染界面、命令行、转换模块、Python 文档引擎包装层及构建/发布脚本。
基线为提交 `70e24bfe964ec819dcc4a10512f5b5b5d83a527f`，审阅日期为 2026-09-03。
外部引擎二进制和模型权重不属于源码审阅，也不能据此声称完成真实引擎验收。

修改集中在三个有测量或可复现证据的路径：

- `image.js`：逐页解码和压缩，用累计字节数计算 PDF 索引，不再反复拼接整份 PDF 前缀；
  按写入端消耗速度生成数据，压缩使用异步 zlib。空白页图像仅在当前任务内复用。
  使用短名称、独占创建的同目录临时文件，避免给长文件名追加后缀导致超限。
  全部页面写完并关闭句柄后才发布结果；解码、写入或发布失败时清理临时文件，保留已有输出。
- `server.js`：独立引擎同时探测，并发调用共用同一个待完成任务。
  Office 不可用时保留诊断信息，意外失败允许后续重试。
  清理模块拆分后遗留的 81 个无用导入绑定及废弃的 Tesseract 缓存。
- `public/app.js`：每次选择中，同一规范化扩展名只查询一次目标格式，不跨选择缓存失败。
  旧识别结果不能覆盖新选择或已清空的列表。
  转换进度只替换对应行，合并任务一次性初始化队列显示。
  队列状态改在重置下载后初始化，修复图片上移/下移报错；继续通过 DOM API 和 `textContent` 渲染。

未调整依赖、包版本、转换参数、OCR/表格质量阈值、资源预算、许可证/品牌、安全设置或 Windows 7 构建配置。
尤其没有把高内存转换任务改为并行执行。

## 复现 PDF 性能对比

```sh
node scripts/benchmark-image-pdf.js --baseline 70e24bfe964ec819dcc4a10512f5b5b5d83a527f --samples 3
```

脚本使用确定性的 512×512 RGB 噪声图片，每次测量启动独立进程，交替执行新旧版本，
并验证输出 SHA-256 一致。结束后删除测试图片和生成的 PDF。
只使用可信基线：脚本会在当前依赖环境下执行指定提交中的 `image.js`。

测量快照：Linux x64、Node.js 24.19.0，每组 3 次取中位数；测量期间未运行全量 JavaScript 测试。

| 页数 | 耗时：优化前 → 后（毫秒） | 峰值驻留内存：前 → 后（MiB） | Buffer.concat 累计拼接量：前 → 后（MiB） |
|---|---:|---:|---:|
| 8 | 756 → 405 | 123 → 75 | 93 → 6 |
| 24 | 3948 → 1101 | 203 → 95 | 712 → 18 |
| 48 | 12800 → 1998 | 322 → 94 | 2720 → 36 |

三组 PDF 在优化前后逐字节一致；48 页输出为 37,782,976 字节。
这些合成样本结果不能外推为所有格式、图像内容、硬件或 Windows/macOS 安装环境的保证。
峰值驻留内存是单个测量进程的内存高水位；累计拼接量是总拷贝量，不是同时占用的内存。

## 暂缓的高风险工作

- 合并 DOCX 的重复 ZIP 读取，需要保留 WPS 编号、CRC 修复和内嵌资源行为，并使用真实文档验证。
- Python 解析会保留逐步增长的清单，并重复扫描输出预算状态；修改后需要重建锁定引擎并验证代表性扫描件。
- Python 包装层仍声明 500 页上限，与通用 PDF/OCR“不限制页数”的表述存在原有不一致；
  本次没有为了性能改动而放宽资源保护。
- 转换进行中选择/清空队列，需要单独设计取消行为和任务归属；本次旧识别结果保护不等同于转换取消。
