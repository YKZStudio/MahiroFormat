# 0.7.3 本地修复与审查记录

2026-09-14，作者：牢蜂（LaoFeng）。本候选针对不同版本/渠道的白屏、LibreOffice 初始化弹窗和设置迁移 EXDEV 报错，并检查桌面、转换、保存、设置、缓存、安全及打包链路。基于 0.7.2 的提交 `2750b4087f5b31cd8f516d632262ce88820770d0` 在隔离副本实现；源码版本不代表已安装或已上架。

## 已复现并修复

- 本地导航被代理阻断、渲染崩溃或脚本缺失时只有空窗口：应用会话显式直连；补充主进程原生错误提示、用户重试和就绪监测。加载错误页不再记为成功；恢复后的旧提示不重载已恢复工作。
- LibreOffice 配置初始化在深路径/不可写配置位置失败，原生弹窗可没有 stderr 并卡住：采用短、独占且实际可写的配置目录；启动超时结束本次进程树，Store 验证共用策略，失败仅影响 Office。
- EXDEV 回退复制中途失败会损坏设置：保留上一次完整配置供恢复；原有设置降级不阻断转换的行为保留。
- 转换中清空/重新选文件会混入旧请求；慢识别会覆盖新选择：冻结任务入口，按快照执行，并拒绝过期识别/扫描结果。
- 连续同名 Word→Markdown 会覆盖旧图片或继承旧附件：每个结果使用独立图片目录，保存仍保留用户文件名与相对链接。
- 图片 PDF/ZIP 写流错误会结束进程、损坏 ZIP 解压可一直等待：绑定完整流生命周期，将失败交回请求。
- qpdf 缺失时分组拆分忽略每组页数：回退遵循相同分组。加密 PDF 合并与无法解密的拆分回退明确拒绝，不生成空正文伪成功结果。
- 启动清理可能删除超过一天但仍存活实例的结果或同名前缀备份：只检查精确 PID 后缀与确已退出的进程。Office 不再自动删除其他代际缓存。
- 批量保存到不支持硬链接的目标会失败：添加排他复制回退，仍拒绝覆盖同名结果；诊断导出也使用独占临时文件发布，写入失败保留旧文件。
- 转换 API 允许其他 localhost 端口来源：收紧到当前监听的精确 127.0.0.1 origin，保留无浏览器 Origin 的 CLI。
- APPX 默认 PowerShell 5.1 打包时损坏 Node 内联参数：把目录校验写到本次独占脚本文件后执行，实际完成封包与校验。
- 首轮远程 macOS CI 发现 Office 超时清理未建立独立进程组：`execFile` 不转发 `detached`，改为实际创建进程组的进程启动方式，同时保持输出上限和 Windows 精确进程树清理。深 TEMP 冒烟测试也改为按平台检查是否使用过回退目录。

## 验证边界

- 用户截图来自不同版本/渠道；尚未在原反馈机器或正常 Store 安装容器复测。无法据此保证任意安全软件拦截、损坏系统或磁盘故障均可自动修复。
- 更深的自定义引擎缓存位置仍可能使 LibreOffice 原生程序退出：本次长根的缓存验证返回 3221226505，短根成功；不能仅据该错误码判定具体原生原因，不能将配置目录回退描述为解决所有引擎资源长路径。失败仍拒绝该 Office 引擎，非 Office 保持可用。
- 非 NTFS 保存通过真实文件复制与不支持硬链接错误注入验证，未使用实体 FAT/exFAT 设备；复制完成后才报成功，但断电时不保证新文件原子可见。
- 保留旧 Office 缓存有磁盘占用代价。未知锁、磁盘损坏和断电事务不作额外保证。
- 缺少的 OFD、Gutenberg、特定 OCR/PDF 样本列为跳过，不计通过。普通极大输入仍受既有引擎和内存约束，未把占位上限宣传为无限能力。
